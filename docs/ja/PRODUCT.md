# プレイヤー向け gs-mapedit: 製品計画

*これは英語版 [PRODUCT.md](../PRODUCT.md) の翻訳です。内容が異なる場合は英語版が最新です。*

**対象者:** 技術的な予備知識のないファンや MOD 制作者。つまり、ターミナル、16 進数、C、git、ビルドシステムを使わない人たちです。
**提供形態:** インストーラー付きのパッケージ化されたデスクトップアプリ。
*（プロジェクトオーナーが決定、2026-10-20。）*

現在あるエンジン層は、引き続き土台として残ります。これにはファイル形式、バイト単位で正確な保存、不変条件、シーンテーブルのフック、ビルドが含まれます。この計画は、プレイヤーが目にする層についてのものです。

## 原則

1. **コードではなく、名前・絵・場所で。** プレイヤーが目にする値はすべて、名前が付いているか、プレビューされるか、マップ上に表示されます。生の数値は「詳細設定」の切り替えの奥に置きます。
2. **1 つの意図に 1 つの操作。** 「Herb 入りの宝箱を追加する」は、マーカーのリスト、コリジョン、シーンのイベント、新しいフラグに関わるとしても、1 つの操作になります。
3. **ゲームを気づかないうちに壊すことはできない。** 不変条件は現在と同じように強制され、平易な言葉で説明されます。「このドアはまだどこにもつながっていません。」（✅ チェックボタン。毎回のビルドの前にも実行されます。）
4. **いつでもワンクリックでプレイ。** 編集して、プレイ。ビルドは失敗しない限り見えず、失敗はコンパイラーの出力ではなく案内として読めるようにします。
5. **ROM を配布しない。** MOD はパッチファイルとして共有し、プレイヤーは自分のカートリッジの吸い出しにそれを当てます。

## プレイヤーがすること（行動 → 画面）

| 行動 | 画面／操作 | エンジン部品（あるか？） |
|---|---|---|
| ゲームの場所を探検する | **ワールドビュー:** 地上世界と、すべての町／ダンジョン、つながりの表示 | レンダラー ✅、つながりビュー ✅（場所ごと）、地上世界のレンダラー（研究用プロトタイプ） |
| マップの一部を塗り直す | **ペイント:** テーマ別のタイルパレット、ブラシ、塗りつぶし、領域のコピー／貼り付け | ブロックのペイント ✅、塗りつぶし／コピー／領域 ❌ |
| 歩ける場所を変える | **通行設定ブラシ:** 歩ける／通れない／段差／はしご／水を、すっきりしたオーバーレイで表示 | コリジョンのペイント ✅、**名前付きコード ❌（要調査）** |
| ドアを動かす／行き先を変える | ドアをクリックし、行き先のマップ上をクリックして行き先を選ぶ | ✅ ドアツール |
| 宝箱やエナジーストーンを追加／移動する | 宝箱を置き、中身を選ぶ（アイコン付きのアイテム選択、コイン、ミミック） | ✅ 宝箱ツール（アイテム、コイン）、ストーンは移動のみ |
| 人物を配置／移動する | スプライトのプレビュー付きで NPC をドラッグし、セリフを見て編集する | 位置 ✅、**スプライトのプレビュー ❌、セリフの参照 ❌** |
| 試す | **プレイ:** ビルドして、そのマップでエミュレーターを開く | ワンクリックのプレイ ✅（保存、チェック、ビルドし、編集中の場所で開く） |
| 共有する | **MOD を書き出し:** パッチファイルと説明 | ✅ 標準ビルドから MOD ビルドへの BPS |
| 間違いを元に戻す／やり直す | 履歴パネル、「このマップをリセット」 | 元に戻す ✅（セッション中のみ）、永続的な履歴 ❌ |

## 名前付け層（要調査、主に参照作業）

- **コリジョンコード:** 壁、床、段差、よじ登る場所、調べる場所、危険地帯、出口、宝箱。出典: `step.c`、`events.c`、研究ドキュメント。
- **シーン:** 表示用の `scenes.s` の名前と地域名（ゲーム自身の地名）。
- **アイテム:** `include/item_ids.h` の名前と、ゲームのグラフィックからのアイテムアイコン。
- **スプライト:** スプライト ID → 名前と、オブジェクトのグラフィックからのプレビュー画像。
- **セリフ:** メッセージ ID → `text/en.po` のテキスト（10,724 項目）。
- **フラグ:** `include/flags.h` の名前と、新しい宝箱フラグ（≥ 0xe00、未使用）の割り当て器。

## パッケージ化のアーキテクチャ（推奨）

- **シェル:** PyInstaller バンドル内の pywebview（ネイティブの WKWebView）。Python、サーバー、ページを収めた 30 MB の `.app` 1 つです。*（2026-10-22 に Tauri から変更: バックエンドはすでに Python で、Tauri では今のところ利点がないのに Rust のツールチェーンが加わるため。バックエンドが Rust に移る場合、Tauri は選択肢として残ります。）*
- **バックエンド:** 現在の Python サーバーを、同じプロセス内で。
- **ゲームのソース:** アプリが、私たちが検証した固定コミットの alchemy をダウンロードします。プレイヤーが git を目にすることはありません。更新は明示的に行います。「新しい alchemy のバージョンがあります。テスト済み ✓」。
- **ツールチェーン:** 最も難しい部分です。
  - alchemy には、固定されたコンパイラー（ソースからビルド）、binutils、そして独自の C ツール（libpng）が必要です。
  - 計画: これらをプラットフォームごとに CI でビルドし、ビルド済みバイナリとして同梱します。コンパイラーは GPL なので、ソースを公開します。
  - プラットフォーム: まず macOS（Intel + Apple Silicon）、次に Windows（alchemy は Windows を WSL 経由でしか公式にサポートしていないため、ツールのネイティブ移植がリスクです）、その後 Linux。
- **パッチ:**
  - 標準ビルドは製品版 ROM とバイト単位で同一なので、パッチ = diff(標準ビルド, MOD ビルド) で、製品版 ROM に一切触れずにローカルで計算できます。
  - プレイヤーは任意の BPS パッチャー、または私たちのアプリで、それを自分の吸い出しに当てます。
- **テストプレイ:** mGBA（MPL-2.0）を同梱するか、インストール済みのものを検出します。デバッグ用の開始地点が使えれば、編集したマップで起動します。

## マイルストーン

1. **現在のアプリにプレイヤー向け UI を。** ここにあるものはすべて、そのままデスクトップのシェルに引き継がれます。内容:
   - 名前付け層
   - 通行設定ブラシ
   - クリックでつなぐドア
   - アイテム／スプライトの選択
   - 宝箱を追加する操作
   - 平易な言葉での検証
   - ワールド／つながりビュー
2. **パッケージ化の試作（macOS）:** ✅ アプリバンドルと初回セットアップ（alchemy をダウンロードし、一度ビルドする）。✅ ツールチェーンの同梱（Homebrew 不要）。残り: 署名／公証（Developer ID が必要）、Apple Silicon ネイティブビルド、本当にまっさらな Mac でのテスト。成功 = まっさらな Mac が、ターミナルを使わずにゼロから「プレイ」までたどり着くこと。
3. **パッチの書き出し** ✅（BPS、rom.sha1 と照合）。インポート（ほかの人のパッチをアプリ内で当てること）はまだこれから。
4. **地上世界の編集**（SPEC.md の段階 4–5）をプレイヤー向け UI で。
5. **Windows と Linux のパッケージ化。**

## リスク

- **ツールチェーンの移植性（Windows）。** alchemy のビルドは Unix のシェルを前提にしています。WSL との統合や、小さな C ツールのネイティブ移植が必要になるかもしれません。
- **上流の変化。** alchemy は毎日変わります。コミットを固定し、更新はラウンドトリップとレンダーオールのチェック、そしてテストビルドに通ってから行います。
- **「意味」の範囲。** 一部のコリジョンコードやイベントの種類は、alchemy でさえまだわかっていません。不明なものは見えるままにし、「不明（詳細設定）」とラベルを付けます。
- **法的な姿勢:** ROM、抽出したアセット、ビルドしたゲームは決して配布しません。プレイヤーが用意するものは何もなく（The Broken Seal はソースからビルドされます）、アプリが alchemy を自分でダウンロードします。

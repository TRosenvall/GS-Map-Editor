# gs-mapedit: エディターの仕様とビルド計画

*これは英語版 [SPEC.md](../SPEC.md) の翻訳です。内容が異なる場合は英語版が最新です。*

範囲: alchemy のソースツリーの上に作られた、**Golden Sun: The Broken Seal** 用のマップエディター。**ローカルマップ**（町、ダンジョン、屋内）と **地上世界** を扱います。The Lost Age はローカルマップの形式が共通なので、後から少ない手間で対応できます。その地上世界のエンジンは、alchemy ではまだほとんどがアセンブリです。

エディターは alchemy のソースファイルだけを読み書きします。TSV、PNG、そして C／asm のテーブルの限られた範囲です。ROM には決して触れません。file:line 参照付きの詳しい根拠は `docs/research/`（`rendering.md`、`local-connections.md`、`overworld.md`）にあります。このファイルは決定事項を述べます。

## 基本ルール

1. **バイト単位で正確なラウンドトリップ。** 編集していないものを読み込んで保存すると、ファイルがバイト単位で再現されなければなりません。どのファイルの種類にも、ツリー全体にわたるラウンドトリップのテストがあります。編集していないビルドは引き続き `compare` で OK にならなければなりません。
2. **その場で編集し、挿入せずに追加する。** テーブルの行の位置は識別子です。アクター番号 = 8 + 配置の行。シーン ID = `scenes.s` の行。出口テーブルは普通のシーン番号を使います。行を挿入すると気づかないうちに番号が変わるので、新しい行は末尾に置きます。
3. **保存する前に検証する。** どの操作にも不変条件があります（下記）。エディターは不変条件を破る状態の保存を拒否するか、はっきりと警告します。
4. **ビルドが判定者。** 保存後に `make tbs-en` を実行します。エディターはビルドエラーを表示します。mGBA でのテストプレイが最終確認です。
5. **alchemy を固定する。** 既知のコミットに対して作業します。新しいコミットに移る前に、`tests/roundtrip.py` とレンダーオールのチェック（約 2 分）を実行します。これらは 10 月 19 日のパス再編をすぐに検出しました。

## ローカルマップ

### 描画（実装済み、全 182 マップで検証済み）

- **リソース:** 各マップのパレット、キャラブロック 1–3、シート D は、その `gMaps` の行（`map/maps.c`）から来ており、展開された `gamepak/resource_directory.s` を通じて解決されます。マップ 001、002、108、110 には別の行があります。
- **プレースホルダー:** 128×128 のグリッド全体を行優先でたどったときの k 番目の `0xfff` セルは、上位ニブルを保ったブロック k です（`field/map_grid_convert.s`）。全 182 マップで、プレースホルダーの数は `metatiles.tsv` の行数と一致します。
- **ウィンドウ:** 各レイヤーのウィンドウは、レイヤーの原点にヘッダーの範囲を足した位置から始まり、128 で折り返します。
- **まだこれから:**
  - ブレンドの合成（`blend.tsv`: BLDCNT/BLDALPHA/BLDY）
  - タイルアニメーション（`animation.tsv`、シート D）
  - マップ 047、103、104、147、148 の視差スクロールの基準
  - シーンの入口からの、任意のカメラ範囲

  規則は `rendering.md` にあります。

### 編集できるデータと不変条件

| 対象 | ファイル | 編集 | 不変条件／メモ |
|---|---|---|---|
| セルごとのブロック（3 レイヤー） | `map.txt`、各セルの画像 | 解決済みのブロック ID を塗る | **プレースホルダーエンコーダー** で保存: カウンター k を持って行優先でたどる。ブロック == k のセルは `0xfff`（上位ニブルは保持）と書いて k++、ほかのセルは明示的に書く。全 182 マップで正確な逆変換であることを検証済み。 |
| ブロックの定義 | `cell_pictures.tsv` | 新しい 2×2 のタイルの組み合わせを追加 | 最大 4,095 ブロック。行番号 = ブロック ID。 |
| コリジョンコード | `map.txt`、各セルの動作 | 塗る | レイヤーのウィンドウごと。コード 1–239 はイベント（出口、宝箱）を持てる。 |
| 高さ／形状 | `map.txt`、各セルの形状、+ `shapes.tsv` | 塗る | レイヤーのウィンドウごと。 |
| 宝箱／エナジーストーン | `map.s` の `treasure_spot x, z, id` の行 | 追加／移動／削除 | **id は (x, z) のコリジョンコードと等しくなければならない**: 418/418 で検証済み。1 マップ最大 10 個。終端マーカーの行は `ff ff ff`。中身には、新しいフラグを持つ `SEARCH(SEARCH_CHEST)` イベントがシーンに必要。 |
| タイルアニメーション | `animation.tsv` | 後で | 最大 16 チャンネル。 |

共有ファイル: ブロックは別のマップのフォルダーから来ることがあり、`default/` のセルと属性も共有されています。エディターはファイルが共有されているときにそれを表示し、編集する前に警告します。

### シーンテーブル: 1 つのフックと、エディター専用のオーバーライド

**設計（オーナーの方針）: alchemy のファイルへの変更を最小限に。**
- エンジンは、シーンのすべてのテーブルを、RAM 上にあるシーンオーバーレイのエントリーテーブル `gOverlayArea` を通じて読みます。オーバーレイが読み込まれるのはちょうど 1 か所、`Scene_LoadOverlay`（`system/main_routine.c`）だけです。
- エディターはそこに **1 行** `MOD_SCENE_LOADED(gMainRoutineWork.next, &gOverlayArea);` を追加します。これはビルドが `GSMOD` を定義しない限り何にも展開されないマクロなので、標準ビルドは製品版と一致し続けます。
- `GSMOD` があると、このマクロは `games/tbs/src/mod/` にあるエディターが生成したコードを呼びます。そのコードは、エントリーテーブルの関数ポインター（入口、出口、配置、イベント、領域）を、そのシーンのエディターのオーバーライドテーブルを返す関数に差し替え、それ以外はそのままにします。
- ワールドマップもシーンオーバーレイなので、同じフックで地上世界のアイコン、出口、イベントも扱えます。
- シーンの `.c` ファイルは決して書き換えません。オーバーライドテーブルは MOD フォルダーにあり、ROM に入ります。純粋なデータファイル（マップのテーブル、宝箱の行）は引き続き直接編集します。

参考までに、元になるテーブル:

シーンは `games/tbs/src/scene/<place>.c` にあります。5 種類のテーブルを持ち、どれもリテラルとマクロでできたファイルスコープの C 配列です。

| テーブル | 数 | 行のフィールド |
|---|---|---|
| 入口 | 189 | entrance, required_flag, x, y, z, facing, カメラ範囲 |
| 出口 | 99 | kind → (scene, entrance)、任意のフラグ |
| 配置 | 274 | sprite, condition, behaviour, x, y, z, facing, talk facing, flags |
| イベント | 263 | kind/control, trigger, condition, value |
| 領域 | 14 | min/max の箱, condition, exit kind |

エディターはこれらの配列をシーンの `.c` ファイルから *読み*、シーンの元の行でオーバーライドを初期化し、`mod/` にあるオーバーライドのコピーだけを *書きます*。イベント: 既知の制御ワードはデコードし、未知のものはそのまま保持します（約 220 個は生の 16 進数です）。

検証:
- すべての出口の行き先の入口が、行き先のシーンに存在すること。
- 配置の行がテーブルの途中に挿入されないこと（アクター番号のずれ）。
- オーバーレイのサイズが 32 KB 未満に収まること（最大のものの空きは 120 B）。
- x=z=0 の行はコードによって配置されるので、エディターは読み取り専用にします。

出口のグラフは次のとおりです: コリジョンコード／スクリプト／領域 → exit kind → 出口テーブル → (scene, entrance) → 入口の行。エディターはこれを、マップ間のクリックできるリンクとして表示します。

### 新しいマップ（最終段階）

チェックリストは `local-connections.md` §6 にあります。
- リソースディレクトリの空きスロット 25 個、0x08320000 に固定
- `gMaps`（`map/maps.c`）と `scenes.s` に行を追加
- マップの行を `objects.tsv` のオーバーレイより前に追加し、さらにオーバーレイ、音楽、地域名、エンカウントの規則も追加
- グループ ≤ 0x7f、シーン ID < 511

**本当の制限は ROM の空き容量です:** 8 MB の末尾にある空きは、版によって 3.5–43 KB です。本格的な新しいマップを作るには、おそらく ROM を 8 MB 以上に広げる必要があり、それは未検証です。

## 地上世界

| 対象 | ファイル | メモ |
|---|---|---|
| 地面 + オーバーレイのセル | `map/world/blocks.tsv` | 320×512 の u32。チャンクは 16×16 セルで、TSV では 32 個ずつ横に、世界では 16×16 に並ぶ。地面 = チャンク c、オーバーレイ = c + 320。代替 256–319（雪のセット、ストーリー上の橋）。セルのビット: 0–15 ブロック、16–23 足元／イベントコード、24–30 地形の種類（= エンカウント地域）、31 動作バンク。 |
| ブロック | `map/default/cells.tsv` | 4,386 × 4 タイルバイト。**ローカルマップと共有。** 追加を優先。 |
| 通行設定 | `map/default/attributes.tsv` | 8×8 タイルごと、4×4 のニブル。オーバーレイが優先、次に地面、どちらもなければ 7。値 5–12 は歩ける。これも共有。 |
| グラフィック | `graphics/world_map/*.png` | 8bpp、レイヤーごとに 256 タイル、224 色。セット B は雪の北部。PNG のモードとインデックスを保持すること。 |
| 町のアイコン／入る処理 | `scene/world_map.c` の `gWorldMapPlacements`、`gWorldMapEvents`、`gWorldMapExits` | アイコン = アクター 8 + 行。触れるとトリガー 100 + アクター → `EVENT_EXIT` → 出口 → (scene, entrance)。代わりに足元コードになっている項目もある。`gWorldMap_PlaceMarkers`（アクター 11 + i）と揃ったままでなければならない。 |
| ワールドへ出る処理 | `gWorldMapEntrances` | 町の `SCENE_EXIT(n, 2, e)` がパーティーを行 e に置く。 |
| エンカウント | `object/zonedata.c` の規則 → `object/encounter.tsv` のゾーン | 地形の種類 + 動作 → 規則 → ゾーン（104 個の固定行）。 |

注意点:
- ポーズ画面の地図（`picture.png`）は別の絵なので、海岸線を編集した後は手で描き直す必要があります。
- TBS には言語ごとの地上世界の違いはありません。
- The Lost Age の地上世界は異なり（2048 チャンク、32×32）、エンジンもほとんどがアセンブリなので、alchemy がそれをマッチさせるまでは範囲外です。

## 未解決の問題

- ~~ビルドにはプレースホルダーの数 = ブロックの数が必要か？~~ **いいえ。** テスト済み: 441 ブロックに対して 56 個のプレースホルダーを残す編集でもビルドとリンクができます。最初に現れる箇所が塗りつぶされると、エンコーダーはそれ以降のブロックを明示的に書くので、差分は大きくなりますが有効です。ゲーム内での見た目は、まだテストプレイでの確認が必要です。
- `blend.tsv` が BLDCNT を一度も設定しないマップ（039、042、043、114、125）: ブレンドはおそらくシーンのコードから来ています。
- TLA の `scene_points` が何か。`touched_trigger` を書くのは何か。配置の behaviour の値が 2 を超える場合。
- 8 MB を超える ROM が、対象のエミュレーターや実機で正しく起動し、セーブできるか。
